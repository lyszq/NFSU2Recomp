# iOS compatibility and reuse audit

Reviewed 2026-10-20 against the current checkout and the attached reuse memo. This is a source-level architecture audit; it does not inspect or reproduce a game executable or generated game C. The Android recompilation is a different `SPEED2.EXE` build, so its function addresses, generated code, import layout, and binary-specific assumptions are out of scope for reuse.

## Reuse matrix

| Area | Existing macOS source and permission | Semantics and iOS fit | Recommendation and tests |
|---|---|---|---|
| Dynamic TLS | `runtime/win32.c::win32_call`, `tls_slot` / `tls_next` (around lines 190, 389–400). The checkout's root `LICENSE` is MIT and covers these project sources. | The desktop path allocates monotonically from a process-global 128-entry array. `TlsSetValue`/`TlsGetValue` may instead use the pointer at `TEB+0x2c`, conflating dynamic TLS with the static PE TLS vector; fallback values are shared by guest threads. `TlsFree` always succeeds and does not clear or recycle a key. This does not implement per-thread dynamic TLS. | Keep the bounded C core in `runtime/guest_tls.*`: 64 process keys, 64 attached TEBs, dynamic slots at `TEB+0xe10`, and no change to static TLS at `+0x2c`. Its strict unallocated-key error is an explicit runtime policy. `tests/guest_tls_test.c` should cover per-thread raw DWORDs, autoattach/zeroing, all-key and thread limits, key reuse/clear, malformed memory, and failed-preflight atomicity. |
| Critical sections | `runtime/win32_ext.c::cs_for` and `win32_ext_call` (around lines 187–218, 933–957), MIT in this checkout. | A lazily populated 512-entry address table owns recursive pthread mutexes. It does not validate or mirror the guest `CRITICAL_SECTION`; `Enter` on an uninitialized address creates a host lock; `DeleteCriticalSection` is a success stub; `NOCS` restores no-op behavior. Contention releases the global guest lock and later reacquires it, which is a valuable scheduler design clue. The per-host-thread `tl_cs_depth` is not per section, so it cannot validate which guest lock is being left. | Do not link this desktop code into the iOS ABI. Keep `runtime/guest_critical.*` as the checked bridge with owner/recursion state, and reuse only the high-level rule “drop the guest execution lock while blocking.” Keep tests for recursive ownership, wrong-owner calls, contention, guest mirror consistency, delete/recreate, and lock cleanup. |
| Guest threads and scheduling | `runtime/win32_ext.c::CreateThread`, `guest_thread_main`, `guest_pthread_create`, `guest_lock`, and `guest_yield_begin` (around lines 90–94, 301–346, 752–842), MIT in this checkout. | This is not a narrow Win32 shim: it owns a global guest-execution mutex, thread/handle objects, timer and event state, per-thread `CPU`, stack allocation, TEB setup, pthread naming, and desktop diagnostics. It uses a 256 MiB host-thread stack request with a fallback, fixed guest TEB/stack ranges, and Darwin/BSD `kqueue` timing (`<sys/event.h>`). Its TEB uses `+0x2c` for static TLS and `+0x24` for a guest thread ID. | Preserve the current single-guest-thread iOS runner until a real import requires guest workers. If workers are added, extract a small scheduler/CPU lifecycle adapter instead of importing `win32_ext.c`. Test unique/recycled guest IDs, CPU/stack/TEB isolation, exit/resume lifecycle, lock handoff during waits, and TLS values per guest thread. |
| CRT and base Win32 imports | `runtime/win32.c::win32_call`, including `GetVersionExA/W`, `GetModuleHandleA`, `GetCurrentThreadId`, `GetLastError`, and `SetLastError` (around lines 289–411), MIT in this checkout. | The desktop bridge performs raw `MR32` writes. `GetVersionExA/W` does not validate the guest buffer or its size; `GetModuleHandleA` returns the image base for every argument; `GetLastError`/`SetLastError` are stubs. `GetCurrentThreadId` correctly derives the ID from `FS:[0x24]` when mapped, which is a useful ABI convention, not a reason to reuse the dispatcher. | Keep the new iOS API bridge strict and explicit: validate the full guest structure before writing, preserve the chosen XP compatibility policy, set TEB last-error state for invalid buffers, and stop on unknown APIs. Keep ANSI size tests (148/156); implement and test Unicode layouts separately, undersized/oversized declarations, inaccessible/cross-granule pointers, `TEB+0x34`, exact module identity, and unknown imports. |
| Heap | `runtime/win32.c` guest heap (`galloc`, `gsize`, `HeapCreate`, `HeapAlloc`, `HeapFree`, `HeapReAlloc`, `HeapSize`), MIT in this checkout. | The desktop heap is a process-global bump arena. `HeapFree` reports success without reclaiming; reallocation obtains another bump allocation and copies; heap handles are mostly fixed placeholders. That can work for a known desktop trace but is not a general heap contract. | Do not reuse its allocator. Keep the bounded address-space core in `runtime/guest_heap.*` and the API-specific handle/flag policy in its bridge. Test zero-size and zeroed allocation, fixed maximum, growth bounds, invalid/double free, coalescing/reuse, handle isolation, and no state change on failed allocation. |
| Filesystem | `runtime/fileio.c::resolve_in`, `resolve`, `resolve_w`, and `fileio_call` (around lines 27–150 and 176–429), MIT in this checkout. It uses POSIX `open/read/write/pread`, `DIR`, and file descriptors. | This provides useful Windows-to-POSIX behavior: case-insensitive component lookup, separate read and write roots, copy-up for saves, directory enumeration, and overlapped-read completion. It is not safe to reuse path resolution as-is: `resolve_in` strips the drive/root prefix and converts separators, but does not reject `..` components or prevent symlink escape from the selected root. It also receives raw guest pointers and commits/writes buffers directly. The desktop paths and global roots are not an iOS document-picker or sandbox policy. | Adapt the virtual path rules only after replacing host resolution with a root-directory capability (`openat`/component walk, reject traversal, no symlink escape). Keep user-selected game data read-only and saves under an app-owned root. Tests should include mixed separators, case folding, `..`, absolute/drive paths, symlink escape, overlay read/copy-up, overlapped offsets/events, invalid guest buffers, and handle exhaustion. |
| Guest memory and PE loading | `runtime/mem.c::mem_init`, `mem_commit`, fault/watchpoint handlers, and `mem_load_pe` (around lines 28–220), MIT in this checkout. | `mem.c` is a desktop adapter around the portable `guest_memory.*` core. It adds SIGSEGV/SIGBUS diagnostics, alternate signal stacks, a background `mprotect` rearm thread, watchpoints, and an unchecked file-based PE loader. Those are process-wide desktop diagnostics and should not enter the iOS app. | Reuse the extracted `runtime/guest_memory.*` core and authenticated `runtime/guest_pe.*` loader. Keep diagnostics behind a desktop-only adapter. Validate mapping availability and lifecycle on each iOS target; retain tests for wrap/bounds, bitmap boundaries, access protections, aliasing, overlap accounting, and shutdown/reinit. |
| Function dispatch | `runtime/dispatch.c::dispatch_init` and `dispatch_indirect` (around lines 14–36 and 57–137), MIT in this checkout. | The generic address-to-function lookup already lives in `runtime/guest_dispatch.*`. The rest of `dispatch.c` hardcodes this build's text range and generated `g_fn_addr`/`g_fn_ptr`, then routes high addresses to desktop Win32 and COM handlers. Its missing-target fallback can execute a desktop interpreter and finally `POP32(c->eip)`, swallowing an unresolved call. | Reuse only `guest_dispatch.*` plus the strict extracted `guest_execution.*` path. Do not reuse this dispatcher or its generated tables. Tests should assert call/return stack semantics and explicit stop on unresolved address, import, unsupported operation, budget/depth limit, or invalid memory. |
| COM / graphics | `runtime/com.c::com_new`, `com_call`, and `com_init` (around lines 63–120, 1825 onward, 4193–4218), MIT in this checkout. | The COM vtable encoding is a useful description of the local guest ABI, but this is a large Direct3D 9/DirectInput/DirectSound implementation coupled to `d3d9_tables.h`, `vsemu`, guest-memory globals, macOS Metal entry points, keyboard/mouse input, and the audio bridge. It is not a platform-neutral COM layer. | Keep the iOS renderer and host interfaces native to this port. Port individual D3D9 semantics only when the actual guest path reaches them; add interface-specific vtable, `this`, stdcall stack-cleanup, refcount, resource, and render-output tests. Do not import the Xbox/NV2A renderer. |
| Audio | `runtime/audio.m::mix_into`, `audio_register`, CoreAudio callbacks, and `audio_init` (around lines 81–120, 234–341, 408–513), MIT in this checkout. | The mixer and guest-buffer cursor logic are separable C-like code, but the file is Objective-C and owns macOS CoreAudio `AudioUnit`/`AudioQueue` setup. It selects `kAudioUnitSubType_DefaultOutput`; the iOS host still needs its own session, route/interruption, and output-component lifecycle. The callback is a native audio thread protected by `g_slock`, not a Win32 guest critical section. | Consider extracting and testing only the sample conversion/mixer once iOS audio is in scope; write a separate iOS output adapter. Test 8/16-bit mono/stereo conversion, loop/cursor behavior, callback underrun, and concurrent guest writes without holding a guest execution lock in the audio callback. |

## External reference and provenance

The attached memo points to `codepdbh/nfsu2-recompiled` Android sources. The current public README identifies its tested executable as `SPEED2.EXE` (4,800,512 bytes, SHA-256 `f9dd86c054878ce6276beb07c1fd61874f7a1e4bf1f241b084c65b73e24168a7`); this differs from this checkout's stated 4,788,224-byte / `8f6a9ae2…` executable. Treat it only as a different-build behavioral reference.

The fetched Android [`guest_kernel.inc`](https://github.com/codepdbh/nfsu2-recompiled/blob/main/android/app/src/main/cpp/guest_kernel.inc) is C++ runtime code: it uses a 1,088-entry TLS bitmap and `thread_local` values, plus a `recursive_mutex` critical-section map with explicit guest-state updates and scheduler yields while contended. Those are design comparisons, not drop-in C modules: capacities, thread model, data structures, and execution-lock policy differ. The memo's `guest_threads.inc` and `docs/THREADING.md` locations could not be fetched at those exact paths during this review; that does not establish that no equivalent document exists elsewhere.

The current upstream README says that code authored in its repository is MIT-licensed, while the expected root `LICENSE` URL returned 404 in this review. The fetched bridge file has no separate license header. Before copying any external source, pin a commit, verify its exact file and dependency provenance, and retain the applicable notices; this audit copied no Android implementation. The local checkout's `LICENSE` is MIT.
